# إصلاح توقف رد الوكيل عند تغيير محافظة الشحن

## التشخيص المؤكد
- الـAgent Run ينجح في حفظ رسالة العميل وامتلاك قفل المحادثة، ثم يتوقف قبل إنشاء رد المساعد أثناء انتظار `identityPromise`.
- نقطة التوقف هي `extractProfileFieldsWithAI()` في `src/routes/api/chat-ai.ts`؛ استدعاء AI عند السطر الحالي 435 لا يملك مهلة زمنية، بينما يتم انتظاره ضمن `identityPromise` قبل بناء الرد.
- سجل AI Gateway يثبت وجود طلب `gemini-2.5-flash-lite` من هذا المسار ظل 184,994ms ثم أُلغي بـHTTP 499 وخرج بصفر tokens. لذلك لا يصل التنفيذ إلى إدراج رسالة `assistant` أو ربط `agent_reply_id`، ويبقى الطلب ظاهريًا بلا رد. تعديل retry الخاص باستدعاء الوكيل الرئيسي لا يشمل هذا الاستدعاء التمهيدي.
- توجد مخاطرة مماثلة في استدعاء الوكيل الرئيسي: التعليق يقول إن له timeout، لكن `fetch` لا يحتوي حاليًا على `AbortSignal.timeout`. سيتم إغلاق هذه الفجوة ضمن نفس حد الحماية، دون تغيير منطق الطلب.

## التنفيذ
1. إضافة مهلة زمنية محدودة إلى استدعاء استخراج بيانات العميل، مع الإبقاء على سلوكه الحالي عند الفشل: يرجع `{}` وتستمر الدورة بدل تعطيل الرد.
2. إضافة المهلة المفقودة إلى استدعاء الوكيل الرئيسي حتى تدخل مهلات الشبكة فعلًا في مسار retry الحالي.
3. عدم تعديل دمج `order_state` أو مطابقة منطقة الشحن أو التسعير أو إنشاء الطلب أو خصم المخزون.
4. إضافة اختبارات انحدار تثبت أن تعطل الاستخراج لا يمنع الوصول لتوليد/حفظ الرد، وأن تغيير `الغربية` إلى `القاهرة` يُقرأ كمنطقة مغطاة ولا يرث سعر المنطقة القديمة.

## التحقق
- تشغيل اختبارات الشحن وحالة الطلب وتسلسل Agent Run والاختبار الجديد.
- إعادة سيناريو `الغربية → القاهرة → تأكيد → طريقة الدفع` عبر واجهة الدردشة، والتحقق في كل خطوة من ظهور رسالة `assistant` فعلية ومن عدم تغير السعر أو المخزون قبل خطوة إنشاء الطلب الصحيحة.
- مراجعة سجلات الخادم وAI Gateway بعد التجربة للتأكد من عدم بقاء Run معلقًا ومن اكتمال إدراج الرد بعد تغيير المحافظة.
